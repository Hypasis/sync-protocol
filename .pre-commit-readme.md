# Pre-commit Setup Guide

This repository uses [pre-commit](https://pre-commit.com/) to ensure code quality and consistency.

## Installation

Pre-commit is already configured in this repository. If you're setting up a new development environment:

### macOS (using Homebrew)
```bash
brew install pre-commit
```

### Linux/Windows (using pip)
```bash
pip install pre-commit
```

## Setup

After installing pre-commit, run the following command in the repository root:

```bash
pre-commit install
```

This installs the git hooks that will run automatically before each commit.

## What Gets Checked

The pre-commit hooks will automatically:

1. **General File Checks**
   - Remove trailing whitespace
   - Fix end of file issues
   - Validate YAML files
   - Check for large files (>1MB)
   - Detect merge conflicts
   - Check for case conflicts
   - Normalize line endings to LF
   - Detect private keys

2. **Security Checks**
   - **Gitleaks**: Scan for hardcoded secrets, API keys, passwords, and tokens
     - Prevents accidental commit of sensitive data
     - Custom rules for blockchain/crypto projects
     - Configurable via `.gitleaks.toml`
     - False positives can be added to `.gitleaksignore`

3. **Go-Specific Checks**
   - Format code with `go fmt`
   - Organize imports with `go imports`
   - Run `go vet` for suspicious constructs
   - Run `go mod tidy` to clean dependencies
   - Run `golangci-lint` for comprehensive linting

## Usage

### Automatic Checks
Pre-commit hooks run automatically when you commit:
```bash
git commit -m "your commit message"
```

If any checks fail, the commit will be blocked and files may be auto-fixed. Review the changes and commit again.

### Manual Checks

Run on all files:
```bash
pre-commit run --all-files
```

Run on specific files:
```bash
pre-commit run --files path/to/file.go
```

Run a specific hook:
```bash
pre-commit run go-fmt --all-files
```

### Skip Hooks (Use Sparingly)

If you need to skip hooks for a specific commit (not recommended):
```bash
git commit -m "your message" --no-verify
```

## Updating Hooks

To update to the latest versions of the hooks:
```bash
pre-commit autoupdate
```

## Troubleshooting

### Hooks are slow
Pre-commit caches hook environments. The first run is slower as it sets up the environments.

### Golangci-lint not found
Install golangci-lint:
```bash
# macOS
brew install golangci-lint

# Linux
curl -sSfL https://raw.githubusercontent.com/golangci/golangci-lint/master/install.sh | sh -s -- -b $(go env GOPATH)/bin
```

### Gitleaks not found
Install Gitleaks:
```bash
# macOS
brew install gitleaks

# Linux
wget https://github.com/gitleaks/gitleaks/releases/latest/download/gitleaks_linux_x64.tar.gz
tar -xzf gitleaks_linux_x64.tar.gz
sudo mv gitleaks /usr/local/bin/
```

### Goimports not found
Install goimports:
```bash
go install golang.org/x/tools/cmd/goimports@latest
# Make sure $(go env GOPATH)/bin is in your PATH
export PATH=$PATH:$(go env GOPATH)/bin
```

### Clean hook cache
If you encounter issues:
```bash
pre-commit clean
pre-commit install --install-hooks
```

### Pre-commit reports many errors
The current configuration will report existing code quality issues but won't block commits. You can:
1. Fix issues gradually as you work on related code
2. Run `pre-commit run --all-files` to see all issues
3. Adjust [.golangci.yml](.golangci.yml) to make checks more/less strict

### Gitleaks reports false positives
If Gitleaks flags legitimate code (like test fixtures or example configs):

1. **Run a scan to get the fingerprint:**
   ```bash
   gitleaks detect --config .gitleaks.toml --verbose --no-git
   ```

2. **Add the fingerprint to `.gitleaksignore`:**
   ```
   path/to/file.go:rule-id:line-number
   ```

3. **Or adjust rules in `.gitleaks.toml`:**
   - Add paths to allowlist
   - Add regex patterns to exclude
   - Modify custom rules

### Gitleaks blocks a commit with real secrets
If Gitleaks correctly identifies a secret:

1. **Remove the secret** from your code
2. **Use environment variables** instead:
   ```go
   secret := os.Getenv("API_KEY")
   ```
3. **Add the variable to `.env.example`** as documentation:
   ```
   API_KEY=your-api-key-here
   ```
4. **Ensure `.env` is in `.gitignore`**

**Never use `--no-verify` to bypass Gitleaks!** This defeats the purpose of secret scanning.

## Gitleaks - Secret Scanning

Gitleaks scans your code for hardcoded secrets before they reach the repository. This prevents:
- Accidentally committing API keys
- Leaking database credentials
- Exposing JWT secrets
- Revealing private keys

### How It Works

1. **Pre-commit**: Scans staged files before commit
2. **Custom Rules**: Tailored for blockchain/crypto projects
3. **Smart Filtering**: Ignores test files and example configs
4. **Fingerprint-based**: Allows specific false positives via `.gitleaksignore`

### Testing Gitleaks

Scan the entire repository:
```bash
gitleaks detect --config .gitleaks.toml --verbose
```

Scan specific files:
```bash
gitleaks detect --source path/to/file.go
```

Generate a report:
```bash
gitleaks detect --report-path gitleaks-report.json
```
